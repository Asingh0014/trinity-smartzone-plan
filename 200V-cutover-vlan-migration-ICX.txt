!=============================================================================
! 200V VLAN migration - main cutover, all switches
! Ruckus ICX, FastIron 10.0.10g
! Change window: Friday 9 October 2026 from 6:00 pm (outage window to Sunday 11 October, 5:00 pm)
! Source: 200V Device Port List.xlsx, 200V Devices tab, Status = To do
!=============================================================================
!
! Scope: untagged VLAN on 340 access ports across 5 switches
!   switch-200V-LT2-1           192.168.122.12     16 ports
!   switch-200V-stack-lv3       192.168.122.22     84 ports
!   switch-200V-stack-lv4       192.168.122.21     89 ports
!   switch-200V-stack-lv6       192.168.122.11    145 ports
!   switch-200V-Tutorial-6.03   192.168.122.15      6 ports
!
! VLAN mapping
!   1230 (200V_av       ) -> 2700 (VL-av-01       )  242 ports
!    100 (management    ) -> 2010 (VL-wifimgmt-01 )   37 ports
!   1272 (200V_av       ) -> 2700 (VL-av-01       )   37 ports
!   1240 (200V_staff    ) -> 2700 (VL-av-01       )   13 ports
!   1240 (200V_staff    ) -> 2800 (VL-print-01    )    6 ports
!   1212 (200V_IPcam    ) -> 2600 (VL-cctv-01     )    4 ports
!   1213 (200V_building ) -> 2510 (VL-bac-01      )    1 ports
!
! Not in this file
!   - 60 pilot ports moved on 5 Oct (already done)
!   - 6 devices on the Not found tab (Review items 15-20, find on site)
!   - Ports without a listed device (Ports without device tab, Review sections 3-4)
!   - switch-200V-8, LT2-2 and LT2-3: no listed devices to move
!
! Before starting
!   - Running-config backups of each switch: taken via SmartZone on 6 Oct (done)
!   - Trinity to confirm DHCP reservations are in place on the new subnets
!   - lv6: 2600 and 2700 run without spanning-tree until the system-max change
!     (system-max-spanning-tree-40-ICX.txt) is done. It is done first on the night
!   - Tutorial-6.03: no remote access. Its section is run over a console cable
!     on site. Paste one block at a time: the console is slower than SSH
!
! How the change works (same as the pilot)
!   - ICX will not add a port untagged to a new VLAN while it is still untagged
!     in another, so each CHANGE block removes the old VLAN first
!   - Only the untagged VLAN changes. Tagged VLANs on AP ports and other trunk
!     ports are not touched
!   - PORT BOUNCE (disable, wait 10 s, enable) makes DHCP devices request an
!     address on the new subnet. It does not remove PoE
!   - Ports marked '*' in the port lists had their port taken from the 200V MAC
!     tab, not the master list (Review section 1). Confirm in the pre-check
!
! Wi-Fi: the 200V APs move to the new SSIDs in SmartZone. Trinity Wireless uses
!   VLAN 2300, already tagged on the AP ports. Trinity Visitor and eduroam use
!   VLAN 2900, which is not, so each switch with APs has an 'AP PORTS: ADD VLAN
!   2900' block (lv3, lv4, lv6, LT2-1; 40 ports). It only adds tagging: no impact.
!
! Order: one switch at a time, LT2-1 first (smallest), then lv3, lv4, lv6,
! then Tutorial-6.03. Per switch: PRE-CHECK > CHANGE > PORT BOUNCE > VERIFY >
! write memory. If a switch fails verification, run its ROLLBACK before the next.
!=============================================================================
